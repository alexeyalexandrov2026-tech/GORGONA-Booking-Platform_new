# GORGONA configuration publication acceptance — 2026-10-04

Package D (CORE-02) is technically verified on commit `5320c4a`, branch `codex/universal-business-foundation`, repository `alexeyalexandrov2026-tech/GORGONA-Booking-Platform_new`. Later commits do not extend this acceptance to changed application code.

An owner or manager saves a configuration draft that pins a business profile revision and the optional modules to enable, previews what changes and what stops, validates it on the server and publishes it; the previous published version is kept as replaced. Only modules that are at least technically verified can be enabled (booking today); planned modules are listed with their readiness and limits. When a published configuration turns booking off, no path can create a booking or reschedule — the workspace, branch staff, delegates, the customer site and development holds all receive 409 `MODULE_DISABLED` — while cancellations, confirming an existing hold, history and reads continue. Businesses that never published keep their previous behaviour. Readiness records for the 28 scenarios and 39 profiles are kept apart from the industry catalog. Custom fields and process configuration (the rest of master plan §4) are outside this increment. See [ADR-0019](../../../adr/0019-configuration-publication-and-modules.md).
