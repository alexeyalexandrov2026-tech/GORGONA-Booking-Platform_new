Как устроен возврат:

- документ вида `return` называет один исходный документ — приёмку или списание того же
  владельца; строка называет строку источника и количество, материал берётся из неё;
- направление обратно источнику: по приёмке — расход (`supplier_return`, `entry_error`),
  по списанию — приход (`unused`, `entry_error`);
- предел: все возвраты строки не больше её количества. Триггер строки проверяет это под
  блокировкой исходной строки (`for update`; для неё выдано право `UPDATE (line_no)`,
  любое изменение строки по-прежнему отклоняет триггер неизменяемости). Отказ — `GBS03`,
  в API — 409 `STOCK_RETURN_EXCEEDED`;
- доля суммы исходной строки — `issue_value(остаток суммы, остаток количества,
  количество)`; хранится в `stock_valuations.basis_minor`; триггер оценки считает её сам и
  принимает только её;
- возврат по приёмке: запасы кредитуются по скользящей средней, счёт приёмки из версии
  счетов источника дебетуется на долю, разница идёт на счёт разницы цен текущей версии;
  возврат по списанию: приход по доле стоимости из счёта, который дебетовало списание;
- проводка — одна строка на счёт; сверка целого документа сравнивает набор «счёт, сумма».
  `total_minor` документа — сумма по счёту запасов; у возврата по приёмке проводка может
  быть и при нулевом `total_minor`;
- порядок блокировок правила 16: блокировка книги → исходные строки по номеру → строки
  остатка в порядке «материал, место».

## Как запускать проверки

`runner.py <имя-фазы> <static|full|focused> [файлы pytest]` в каталоге прогона создаёт
новый каталог фазы и отказывается от существующего. Этот runner привязан к этой рабочей
копии: для следующей работы скопировать `runner.py` и `write_record.py` в новый каталог
прогона и до первого запуска исправить в них `ROOT`, имя ветки, основу и имя каталога
записи. Сначала `static` (она пересобирает `web/out`), затем `focused` или `full`; во время
full `api/`, `web/` и `web/out` менять нельзя. Документы в `docs/` runner не хеширует.

`write_record.py <фаза full> <остальные фазы>` пишет `CHECKS.json` до коммита кода: он
требует, чтобы HEAD был основой, и отказывается, если файл изменён после полного прогона.
После коммита сверить идентификаторы объектов коммита с записью.

Полный прогон идёт 22–32 минуты. Перед запуском попросить приложение не давать компьютеру
уснуть и посмотреть, хватает ли памяти и не занят ли диск: browser-тесты чувствительны ко
времени. Чужие процессы не трогать. Упавший тест сначала запустить отдельно на тех же
байтах, затем повторить полный прогон. Прерванный прогон: проверить, что вторая строка
`<фаза>/data/postmaster.pid` — каталог этой фазы, остановить только его
(`pg_ctl stop -D <каталог>/data -m fast -w`), остановить процессы pytest этой фазы и
запустить новую фазу с новым именем.
