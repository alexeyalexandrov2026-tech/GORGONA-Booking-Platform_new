## Обзор чтением

Прочитаны: итоговые `gba.obligation_balance` (0029),
`gba.effective_payment_allocations`, `gba.enforce_settlement_event` и
`gba.assert_settlement_consistent` (0028), кредитная часть
`gba.assert_invoice_consistent`, `gba.external_identity_key` и
`gba.financial_mirror_original` (0030), миграция 0031 целиком, API допуска,
основа сервиса допуска, новый обзорный endpoint, хранилища восстановления web.

- Кредит выпускается только при `R = 0` и `P + C <= A`; резерв и подтверждение
  проверяют `P + C + R <= A` по итоговому балансу. Обе проверки стоят в
  отложенных триггерах и повторяются в сервисе под блокировкой книги.
- Исправление платежа разрешено только в состояниях `reserved` и `sent`, то есть
  внутри собственного резерва расчёта; после освобождения возможно только
  аннулирование, которое уменьшает P. Сценарий «увеличить платёж после
  освобождения, когда остаток занял другой расчёт» состоянием запрещён.
- Реестр допуска не создаёт документов, обязательств, проводок и платежей; все
  четыре признака возможностей ограничены значением `false` на уровне CHECK;
  оценка ограничена `not_checked / suspended / unsupported`.
- Маршруты допуска используют существующие права `FINANCE_READ` /
  `FINANCE_MANAGE` и ту же блокировку книги; аудит и квитанции содержат только
  идентификаторы.

Обхода лимита в прочитанных путях не найдено. Чтение было выборочным.
